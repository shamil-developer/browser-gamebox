# browser-gamebox

Игровой рабочий стол в браузере: готовый [LinuxServer WineGUI](https://docs.linuxserver.io/images/docker-winegui/), Wine и Selkies. Игры выполняются на Linux-ВМ, Mac открывает браузер. Это Wine, не виртуальная Windows; совместимость и скорость каждой игры проверяются отдельно.

Нужна отдельная Ubuntu 24.04 / Debian 12+ **amd64** с доступом в интернет. Для старта ориентир — 4 vCPU, 8 ГБ RAM, 60 ГБ SSD. SSH-пользователь должен быть root либо иметь `sudo -n`. Публично открываем только SSH; контейнер слушает `127.0.0.1`.

## Настройка GitHub

В **Settings → Environments → production** добавь параметры. Все значения задаются явно.

**Variables — обычные настройки:**

| Имя | Что указать |
| --- | --- |
| `SSH_HOST` | IP / DNS новой ВМ |
| `SSH_PORT` | SSH-порт, например `22` |
| `SSH_USER` | Пользователь ВМ с правами выше |
| `SSH_KNOWN_HOSTS` | Строка ключа сервера из `known_hosts`, с проверенным отпечатком; для нестандартного порта — `[host]:port` |
| `DEPLOY_PATH` | Куда класть Compose и playbooks, например `/opt/browser-gamebox` |
| `GAMEBOX_DATA_PATH` | Отдельная папка данных, например `/srv/browser-gamebox` |
| `GAMEBOX_IMAGE` | Официальный образ с тегом или digest; закреплённый вариант ниже |
| `GAMEBOX_PORT` | HTTPS-порт на ВМ, например `3001` |
| `GAMEBOX_USER` | Логин входа в браузере, например `player` |
| `PUID` / `PGID` | UID / GID владельца файлов: `id -u` и `id -g` обычного пользователя ВМ; положительные числа |
| `TZ` | Часовой пояс, например `Europe/Moscow` |

Закреплённый образ:

```text
ghcr.io/linuxserver/winegui@sha256:11b54e3c42d7b9cef20f22ba7cea4dc9767edca36794515ba766c5395bef8e2d
```

**Secrets — приватные значения:**

| Имя | Что указать |
| --- | --- |
| `SSH_PRIVATE_KEY` | Приватный SSH-ключ целиком, включая BEGIN / END; соответствующий публичный ключ должен быть на ВМ |
| `GAMEBOX_PASSWORD` | Пароль входа в браузере, минимум 16 символов |

Настройки передаются по SSH во временный JSON в RAM (`/dev/shm`, права `600`), который удаляется после выполнения, включая ошибку. Серверный `.env` не создаётся; задачи с секретами скрывают вывод. Администратор Docker имеет доступ к переменным контейнера.

## Четыре ручных Action

В **Actions → Run workflow** по очереди:

1. **🔧 Install Ansible** — проверяет и при необходимости устанавливает Ansible на ВМ по SSH.
2. **🐳 Prepare environment** — устанавливает Docker / Compose и создаёт папки данных.
3. **🚀 Deploy gamebox** — скачивает указанный образ, запускает контейнер, проверяет HTTPS с логином и паролем. Повторный запуск обновляет развёртывание.
4. **⏯️ Manage containers** — `start`, `stop` или `restart` существующего контейнера; данные сохраняются.

GitHub использует временную машину для SSH. Ansible выполняется на ВМ. Обновить образ: поменять `GAMEBOX_IMAGE` и повторить Deploy. Остановить игру и сделать резервную копию папки данных перед обновлением.

## Открыть и играть

На Mac, используя свой SSH alias:

```sh
make tunnel HOST=my-gamebox LOCAL_PORT=3001 REMOTE_PORT=3001
```

Все три параметра обязательны. Открыть **https://localhost:3001**, подтвердить самоподписанный сертификат, ввести `GAMEBOX_USER` / `GAMEBOX_PASSWORD`. Терминал держать открытым; `Ctrl+C` закрывает туннель.

Установщики положить на ВМ в `$GAMEBOX_DATA_PATH/games` — внутри рабочего стола это `/games`. Например, `scp ./setup.exe my-gamebox:/srv/browser-gamebox/games/` (путь заменить своим; SSH-пользователю нужны права записи). В WineGUI создать окружение Wine, установить игру и запускать её там. Для установки и сохранений использовать домашнюю папку `/config`.

`config/` хранит окружения Wine, установленные игры, настройки и сохранения; `games/` — загруженные файлы. Обе папки лежат на ВМ вне репозитория и переживают замену контейнера. Резервировать нужно обе. Первую игру, звук и управление проверяем после развёртывания; GPU и игровая производительность этой конфигурацией пока не проверены.
